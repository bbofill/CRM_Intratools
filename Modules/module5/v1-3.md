# Módulo 5 – Data Utilization v1.3

## Introducción

El módulo 5 se encarga de la **extracción, validación y exportación de datos UNEIX y del personal del CRM**, permitiendo al personal autorizado revisar campos incompletos, actualizar registros y generar informes en formato Excel con información consolidada de empleados, grupos, miembros y spinoffs.  
Da soporte a:
- Detección de **campos obligatorios/incompletos** en personas, grupos, reconocimientos y miembros de grupos.
- **Exportación** de:
  - Tablas de UNEIX.
  - Datos de empleados (Excel o CSV configurable por campos).
- Conexión con MSSQL para poder extraer los datos de los visitantes.
---

El acceso a los datos protegidos de los trabajadores se delimita desde los `ajustes` del módulo, al que solo tienen acceso los administradores.

## Base de datos

Este módulo trabaja con múltiples tablas relacionadas con el modelo UNEIX y la información del CRM:

- **people**: datos personales, académicos y de contacto.  
- **residence**: información de residencia actual y dirección.  
- **people_nationality**: nacionalidades asociadas a cada persona.  
- **contract**: datos de contrato laboral, fechas y vinculación.  
- **people_grade**: titulaciones universitarias, grado, máster o doctorado.  
- **people_phd**: información de tesis doctoral.  
- **responsible**: responsables internos o externos de tesis.  
- **people_training**: formaciones o cursos realizados.  
- **people_group**: información de grupos de investigación y pertenencia.  
- **people_supervisor**: supervisor(es) de los trabajadores.
- **group_recognition**, **group_members**, **spinoffs**: información agregada de grupos y entidades vinculadas.  
- **room**, **universities**, **educationGrade**, **training**, **studies**, **cities**, **provinces**, **country**: tablas auxiliares de referencia para traducción de códigos.

## Estructura de archivos

### BACK-END

Las rutas se exponen desde `serveAPI` leyendo `action` en la query:

```go
switch action {
  // --------- EXTRACCIÓN UNEIX ---------
  case "missingMandatoryFields":                  handleIncompleteUsers(apiKey, client, w)
  case "updateFields":                            handleUpdateFields(apiKey, client, w, r)

  case "missingMandatoryFieldsGroups":            handleIncompleteGroups(apiKey, client, w)
  case "updateGroupFields":                       handleUpdateGroupFields(apiKey, client, w, r)
  case "getAllGroups":                            handleGetGroups(apiKey, client, w)

  case "missingMandatoryFieldsGroupRecognition":  handleIncompleteGroupsRecognition(apiKey, client, w)
  case "updateGroupRecognitionFields":            handleUpdateGroupRecognitionFields(apiKey, client, w, r)
  case "getAllGroupsRecognition":                 handleGetGroupsRecognition(apiKey, client, w)

  case "missingMandatoryFieldsGroupMembers":      handleIncompleteGroupMembers(apiKey, client, w)
  case "updateGroupMemberFields":                 handleUpdateGroupMemberFields(apiKey, client, w, r)
  case "getAllGroupMembers":                      handleGetGroupMembers(apiKey, client, w)

  // --------- EXTRACCIÓN EMPLEADOS ---------
  case "exportUneixSpinOffs":                     handleExportUneixSpinOffs(apiKey, client, w)
  case "employeeExport":                          handleExportEmployeeData(apiKey, client, w, r)
}
``` 
**Funciones principales:**

- `handleIncompleteUsers()` – Devuelve los usuarios con campos UNEIX incompletos.  
- `handleUpdateFields()` – Actualiza información UNEIX del usuario.  
- `handleIncompleteGroups()` – Devuelve los grupos con campos incompletos.  
- `handleUpdateGroupFields()` – Actualiza campos de grupo.  
- `handleGetGroups()` – Retorna todos los grupos registrados.  
- `handleIncompleteGroupsRecognition()` – Devuelve grupos de reconocimiento incompletos.  
- `handleUpdateGroupRecognitionFields()` – Actualiza campos de grupos de reconocimiento.  
- `handleGetGroupsRecognition()` – Retorna grupos de reconocimiento.  
- `handleIncompleteGroupMembers()` – Devuelve miembros de grupo con campos faltantes.  
- `handleUpdateGroupMemberFields()` – Actualiza datos de miembros de grupo.  
- `handleGetGroupMembers()` – Obtiene todos los miembros registrados en grupos.  
- `handleExportUneixSpinOffs()` – Exporta la información de spinoffs en formato CSV.  
- `handleExportEmployeeData()` – Genera un Excel dinámico con los datos de empleados según los campos seleccionados por el usuario en el frontend.

- **`exportUneixData.js`** – Control principal de exportaciones UNEIX. Gestiona las solicitudes de exportación a Excel y CSV.

## Flujo general de uso

El flujo de trabajo del **Módulo 5** se divide en tres etapas principales: **detección de faltantes**, **actualización de datos** y **exportación**.

---

### 1. Detección de campos faltantes

Desde el frontend (vistas UNEIX), los usuarios pueden detectar registros con información incompleta.  
Cada tipo de entidad (usuarios, grupos, reconocimientos, miembros) tiene su propio endpoint dedicado.

**Flujo:**
1. El usuario abre una vista como `uneixUsers.html` o `uneixGroups.html`.  
2. El JavaScript asociado (por ejemplo, `usersMissingFields.js`) realiza una llamada a un endpoint como:

GET /module5/api?action=missingMandatoryFields

3. El backend evalúa los registros y devuelve una lista JSON con:
- Identificador del registro.
- Campos obligatorios faltantes.
- Estado general de completitud.

3. b) En el caso de estar exportando la tabla 46 (trabajadores) se hace un get request extra a la base de datos de MSSQL para obtener los datos necesarios de todos aquellos visitantes que hayan estado en el centro por más de 14 días, y se evalúan de la misma manera que los trabajadores del centro.

4. El frontend muestra esta información en una tabla, resaltando los campos incompletos e indicando la acción necesaria.

5. Se puede descargar un CSV que informe de los campos faltantes de cada persona (si tiene `people_id`, es alguien vinculado con el centro, si no, es visitante). Ese csv se puede tratar y hacer llegar a las personas correspondientes encargadas de completar esa información desde el lugar adecuado (RRHH desde módulo 4, actividades desde web users).

---

### 2. Exportación de datos

El módulo ofrece dos tipos principales de exportación: UNEIX (CSV) y Empleados (Excel/CSV).

a) Exportación UNEIX

1. El usuario selecciona la opción “Exportar” desde el panel UNEIX deseado.

2. Se pregunta año relativo al que se quieren exportar los datos.

2. b) En caso de tablas como la 46, se harán preguntas personalizadas relacionadas con cargos concretos. 

3. El frontend llama a la acción correspondiente según la tabla.

4. El backend genera un archivo CSV con formato UNEIX estándar `RMxxyy.csv`, donde xx es el año y yy es la tabla correspondiente, y lo envía al cliente, en caso de los SpinOffs, el frontend lo genera automáticamente sin verificación previa.

5. El archivo se descarga automáticamente.

b) Exportación de empleados (Excel/CSV)

1. Desde employeeExport.html, el usuario selecciona los campos que desea incluir en el Excel.

2. Se envía una solicitud POST:
POST /module5/api?action=employeeExport

con un cuerpo similar a:

```json
{
  "fields": [
    "people_id", "people_name", "surname",
    "contract_start_date", "contract_end_date",
    "totalDedication_hours", "office", "training_name"
  ]
}
```
3. El backend:

- Construye una consulta SQL dinámica con las columnas seleccionadas.

- Realiza la traducción de códigos (países, provincias, universidades, etc.).

- Aplica formatos de celda (fechas, booleanos, horas).

- Deduplica registros repetidos tras los JOIN.

4. Devuelve un archivo Excel employee_data.xlsx listo para su análisis.
