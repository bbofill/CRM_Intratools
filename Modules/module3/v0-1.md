# Módulo 3 – Profile v0.1

## Introducción

El módulo `Profile` gestiona toda la información relacionada con el perfil del usuario dentro de la aplicación. Permite consultar datos personales, revisar notificaciones y gestionar la contraseña del usuario.

Sus funcionalidades principales son:

1 - **Visualización de información personal**: 
    El usuario puede ver su información estructurada por secciones (datos personales, formación, residencia, contratos, etc.), obtenida directamente desde las tablas vinculadas a su perfil.

2 - **Visualización de notificaciones**: 
    En la cabecera de la aplicación aparece una campana que indica el número de notificaciones no leídas.
    Al hacer clic, se accede a la página de notificaciones, donde el usuario puede:
   - Ver notificaciones recibidas (con texto, imágenes o PDFs).  
   - Marcar notificaciones como leídas.  
   - Eliminar notificaciones individuales.  
   La eliminación solo afecta a la relación `notification_user`; si no queda ninguna relación para una notificación concreta, se elimina también la entrada correspondiente en `notification`.


3 - **Modificación de contraseña**:
    Los usuarios pueden modificar desde este módulo su contraseña de acceso a Intratools. 

4 - DEPRECATED - Envío de sugerencias de modificación de información a RRHH:
    Los usuarios pueden indicar qué campos desean modificar y con qué información.

5 - DEPRECATED - Como RRHH, aceptar desde notificaciones el cambio de dicha información:
    Cuando un usuario indica una información que desea modificar, le llega una notificación a RRHH y estos pueden decidir si aceptarla o descartarla. 

## Base de datos

Las tablas a las que accede este módulo son:

### 1 - OPTION TABLES: 
Añadir una entrada a estas tablas hará que aparezca reflejado en las opciones del formulario

- `cities`: código - nombre de ciudad.
- `provinces`: código - nombre de provincia.
- `country`: código - nombre de país - nombre nacionalidad.
- `educationGrade`: código - nombre nivel de estudios máximo.
- `researchArea`: código - nombre - categoría de área de investigación.
- `studies`: código - nombre del grado estudiado.
- `universities`: código - nombre de las universidades.
- `researchGroup`: código interno - código de investigación - nombre y otra información relevante a los grupos de investigación.
- `training`: información relativa a las formaciones.

### 2 - DATA TABLES:

- `people`: información relacionada con los trabajadores. Tabla principal.
- `contract`: contrato(s) de cada trabajador.
- `users`: aquel trabajador (entrada de people) con contrato de tipo 'Contracted worker' se le creará automáticamente un usuario para acceder al sistema.
- `people_grade`: estudio(s) de los trabajadores.
- `people_group`: grupo(s) a los que pertenece un trabajador e información relevante.
- `people_nationality`: nacionalidad(es) de los trabajadores.
- `people_phd`: phd(s) de los trabajadores.
- `people_training`: formacion(es) de los trabajadores.
- `people_supervisor`: supervisor(es) de los trabajadores.
- `residence`: residencia(s) de los trabajadores.
- `responsible`: en caso de que un trabajador esté haciendo un phd (tenga entrada a people_phd) se le pueden asociar responsables.

### 3 - NOTIFICATION TABLES:

- `notification`: crea la notificación con su contenido e información de cración. 
- `notification_user`: cada entrada representa una persona que recibirá la notificación con 'notification_id' indicado y otros campos de permisos. 'profile_applied' DERANGED.

## Flujo general de uso

1. **Acceso al perfil**  
   Desde la página principal (`index.html`), el usuario accede a la sección **Profile**, donde se muestran sus datos personales y laborales divididos en secciones.

2. **Carga de información**  
   - El frontend solicita los datos del usuario mediante el endpoint `?action=profile`.  
   - El backend ejecuta `handleGetUserProfile`, que compila toda la información proveniente de las tablas relacionadas.

3. **Visualización de notificaciones**  
   - El usuario accede a `notifications.html`.  
   - Se realiza una petición `?action=notifications` que devuelve todas las notificaciones asignadas al usuario.  
   - Cada notificación puede incluir texto, imágenes o PDFs.  

4. **Marcar como leída / eliminar notificación**  
   - `PUT ?action=markSeen` actualiza el campo `seen` de la tabla `notification_user` a `1`.  
   - `DELETE ?action=deleteNotification` elimina la notificación para el usuario actual.

5. **Cambio de contraseña**  
   - Mediante `POST ?action=changePassword`, en la página inicial `index.html`, el usuario puede actualizar su contraseña en la tabla `users`.

6. **Funciones deshabilitadas (DEPRECATED)**  
   - `sendProfileSuggestion`, `applyProfileChanges` y `uploadPhoto` permanecen implementadas por si en un futuro se quieren recuperar, pero ya no se utilizan.

## Endpoints


**Base URL:**  
`https://<host>/module3/api?action=<action>`
### Perfil del usuario

| Acción | Método | Descripción | Handler |
|--------|---------|--------------|----------|
| `profile` | `GET` | Devuelve toda la información del perfil del usuario autenticado. | `handleGetUserProfile` |

---

### Notificaciones

| Acción | Método | Descripción | Handler |
|--------|--------|-------------|---------|
| `notifications` | `GET` | Obtiene todas las notificaciones vinculadas al usuario. | `handleGetNotifications` |
| `markSeen` | `PUT` | Marca una notificación como leída (`notification_user.seen = 1`). | `handleMarkNotificationSeen` |
| `deleteNotification` | `DELETE` | Elimina la entrada `notification_user` correspondiente a una notificación. | `handleDeleteNotification` |

---

### Gestión de contraseña

| Acción | Método | Descripción | Handler |
|--------|---------|-------------|----------|
| `changePassword` | `POST` | Permite al usuario modificar su contraseña de acceso. | `handleChangePassword` |

---
