# Módulo 1 – Room Reservation v0.1

## Introducción

El módulo Room Reservation permite la reserva de salas dentro del CRM. Incluye diferentes modalidades de reserva y gestión según el rol del usuario:
- `User`: Los usuarios pueden reservar salas de categoría `office` con ciertas restricciones, como tener que adherirse al horario laboral de 9am a 5pm, no poder reservar los fines de semana o agosto. También pueden cancelar sus reservas próximas. 
- `Admin` y `Manager`: Estos roles pueden reservar sin restricciones todas las oficinas, aulas y auditorio en cualquier horario. Tienen la opción de administrar las reservas de todos los usuarios, con opciones de filtrado por fecha, categoría o usuario para mejor manejo. 

El módulo cuenta con envío de correos electrónicos al confirmar reserva y al cancelar reserva. 

## Base de datos

Para el correcto uso de este módulo, se han creado dos tablas en la base de datos:

- `room` : contiene todas las salas disponibles para reservar (nombre, categoría y código identificador de la UAB).
- `roomBooking` : contiene toda la información necesaria de una reserva, incluyendo email del usuario que la realizó, fechas y motivo.

Este módulo también accede a la tabla users para guardar correctamente la reserva y a las tablas de logs.

BACK-END /Modules/module1/

| Archivo | Descripción |
|---------|-------------|

| Archivo | Descripción  |

| `index.html` | Vista inicial. Muestra formulario de fechas y categorías de sala. Filtra según el rol del usuario. |

## Flujo general de uso

### 1. Consulta de disponibilidad
- Petición desde `index.html`
- `serveAPI` recibe los datos (`startTime`, `endTime`)
- Se consultan las salas de categoría classroom, office o auditorium
- Para cada sala, se revisa si ya tiene reservas en el intervalo deseado
- Se filtran las que están libres y se devuelven al usuario

### 2. Creación de reserva
- Petición desde `confirmation.html` con los datos seleccionados por el usuario
- Se crea la entrada en `roomBooking` con los datos: sala, usuario, correo, fechas y concepto
- Se envía un correo electrónico al usuario con los datos de la reserva

### 3. Cancelación de reserva
- Petición `DELETE` desde `modifyReservation.html` o `viewAllReservations.html`
- Se obtiene la reserva, se elimina y se genera un correo de cancelación personalizado
- Se guarda un log del evento

## Endpoints

### `POST /module/proxy/module1/api?action=getAvailable`

Devuelve las salas disponibles entre un `startTime` y `endTime`.

### `POST /module/proxy/module1/api?action=postReservation`

Guarda una nueva reserva. Es necesario estar autenticado y enviar el JSON con:
- `room_id`
- `start_date`, `end_date`
- `concept`, `email`

### `GET /module/proxy/module1/api?action=fetchAllReservations`

Solo para administradores o gestores. Devuelve todas las reservas.

### `GET /module/proxy/module1/api?action=fetchMyReservations`

Devuelve las reservas futuras del usuario autenticado.

### `DELETE /module/proxy/module1/api`

Cancela una reserva. Se debe enviar el ID de la reserva en el cuerpo JSON.
