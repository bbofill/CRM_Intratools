# Módulo 1 – Room Reservation v1.3

## Introducción

El módulo Room Reservation permite la reserva de salas dentro del CRM. Incluye diferentes modalidades de reserva y gestión según el rol del usuario:
- `User`: Los usuarios pueden reservar salas de categoría `office` con ciertas restricciones, como tener que adherirse al horario laboral de 9am a 5pm, no poder reservar los fines de semana o agosto. También pueden cancelar sus reservas próximas. 
- `Admin`, `Manager` y `Support: Estos roles pueden reservar sin restricciones todas las oficinas, aulas y auditorio en cualquier horario. Tienen la opción de administrar las reservas de todos los usuarios, con opciones de filtrado por fecha, categoría o usuario para mejor manejo. 

Este sistema ofrece la posibilidad de crear reservas múltiples o repetidas en el tiempo. Para ello, se introducirá la primera reserva o evento en el form principal, y se clicará sobre `Set Up Repeating Reservation`, donde se configurará hasta el día seleccionado.

El módulo cuenta con envío de correos electrónicos al confirmar y al cancelar reserva al email proporcionado con la reserva.

También, tiene una conexión unidireccional con los calendarios de las salas que disponen de cuenta Microsoft, ya que todo evento creado desde CRMIntratools, se crea también el el correspondiente calendario. De esta manera, se pueden visualizar los eventos que estén sucediendo en las pantallas de sus correspondientes salas.

La conexión en dirección contraria se puede forzar entrando a `/api/outlook/getAllEvents`, lo que descarga un fichero SQL con todos los eventos registrados en el próximo año, y listo para hacer insert en la base de datos de SQLite. 


## Base de datos

Para el correcto uso de este módulo, se han creado dos tablas en la base de datos:

- `room` : contiene todas las salas (nombre, categoría, código identificador de la UAB y email asociado) y con el campo `reservable` indica si aparece en Room Reservation o no.
- `roomBooking` : contiene toda la información necesaria de una reserva, incluyendo id del usuario que la realizó, email del usuario asistente (puede ser el mismo que la realizó o no) fechas, id del evento en Outlook y motivo.

Este módulo también accede a la tabla `people` para registrar quién hace la reserva y conseguir el email, y a las tablas de logs. 

## Estructura de archivos

BACK-END /Modules/module1/

| Archivo | Descripción |
|---------|-------------|
| `main.go` | Inicia el servidor del módulo 1. |
| `api.go` | Contiene la función principal `serveAPI`, que maneja peticiones POST, GET y DELETE. |
| `types.go` | Define estructuras como `Room`, `ReservaEntry`, `ReqData`, etc. que permiten construir las peticiones json. |
| `imports.go` | Funciones genéricas que permiten la comunicación con la base de datos de SQLite, la creación de logs, el escape de carácteres, etc. |
| `outlook.go` | Conexión con los calendarios de Microsoft, crea los eventos de las nuevas reservas, elimina los de las canceladas, y se puede forzar un get de los próximos eventos registrados en Outlook. |
| `utils.go` | Funcionamiento del módulo, creación de reservas, comprobación de colisiones, etc. |
| `server.go` | Configura y lanza el servidor HTTPS con rutas locales. |
| `assets/` | Plantillas HTML para correos de confirmación y cancelación. |

FRONT-END /GUI/module1/

| Archivo | Descripción |
|---------|-------------|
| `index.html` | Vista inicial. Muestra formulario de fechas y categorías de sala. Filtra según el rol del usuario. |
| `confirmation.html` | Muestra un resumen de la reserva y solicita un correo electrónico para enviar la confirmación. Con `getUserEmail.js`, se recupera el email asociado a la cuenta, si es que tiene, para facilitar este paso. |
| `confirmationRepeated.html` | Ídem para reservas de múltiples eventos. Funciona con `repeatingReservation.js` |
| `modifyReservation.html` | Muestra las reservas futuras del usuario y permite cancelar cualquiera de ellas. |
| `viewAllReservations.html` | Vista exclusiva para administradores y managers. Permite consultar el histórico de todas las reservas. |
| `reservationCalendar.js` | Al lado del título de la pantalla inicial del módulo, hay un icono de calendario. Al clicar sobre este, se abre una vista mensual de los eventos. |

## Flujo general de uso

### 1. Consulta de disponibilidad
- Petición desde `index.html`
- `serveAPI` recibe los datos (`startTime`, `endTime`)
- Se consultan las salas de categoría classroom, office o auditorium
- Para cada sala, se revisa si ya tiene reservas en el intervalo deseado
- Se filtran las que están libres y se devuelven al usuario

### 2. Creación de reserva
- Petición desde `confirmation.html` con los datos seleccionados por el usuario
- Se crea la entrada en `roomBooking` con los datos: sala, usuario, correo, fechas y concepto
- Se envía un correo electrónico al usuario con los datos de la reserva

### 3. Cancelación de reserva
- Petición `DELETE` desde `modifyReservation.html` o `viewAllReservations.html`
- Se obtiene la reserva, se elimina y se genera un correo de cancelación personalizado
- Se guarda un log del evento

## Endpoints

### `POST /module/proxy/module1/api?action=getAvailable`

Devuelve las salas disponibles entre un `startTime` y `endTime`.

### `POST /module/proxy/module1/api?action=getAvailableRepeated`

Devuelve las salas disponibles para todas las "ocurrencias" solicitadas.

### `POST /module/proxy/module1/api?action=postReservation`

Verifica que no se haya realizado ningunar reserva que solape en tiempo-sala con la solicitada. En caso de que continúe disponible, guarda una nueva reserva. Es necesario estar autenticado y enviar el JSON con:
- `room_id`
- `start_date`, `end_date`
- `concept`, `email`, `user_id`

### `POST /module/proxy/module1/api?action=postReservationRepeated`

Similar al anterior pero para todas las "ocurrencias" solicitadas.

### `POST /module/proxy/module1/api?action=getReservationsCalendar`

Devuelve todos los eventos mensuales para su correcta visualización.

### `GET /module/proxy/module1/api?action=fetchAllReservations`

Solo para administradores, support o managers. Devuelve todas las reservas.

### `GET /module/proxy/module1/api?action=fetchMyReservations`

Devuelve las reservas futuras del usuario autenticado.

### `GET /module/proxy/module1/api?action=checkRole`

Devuelve el rol del usuario que ha accedido al módulo para poder verificar su nivel de pérmisos y ventanas a las que puede acceder.

### `GET /module/proxy/module1/api?action=getUserEmails`

Devuelve el email corporativo (o personal si no tiene otro) al frontend para poder auto-rellenar el campo de email en la reserva.

### `DELETE /module/proxy/module1/api`

Cancela una reserva. Se debe enviar el ID de la reserva en el cuerpo JSON.
